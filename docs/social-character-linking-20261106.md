# Подключение существующего персонажа к сайту — 06.11.2026

Опубликовано с резервной копией `/var/backups/social-character-links-20261106T112730Z`.

ВК: независимо проверенный native ID + существующий users + подписанный secure launch открывают прежнего персонажа. При отсутствии подтверждения сайт предлагает сначала открыть игру в ВК и повторить OAuth. Код для ВК не показывается.

ОК: прежние подтверждённые привязки сохраняются. Для неизвестного provider ID сайт выдаёт случайный одноразовый код на 10 минут. В игре внутри ОК кнопка «Подключить сайт» принимает код, показывает имя аккаунта сайта и запрашивает явное подтверждение. Сервер проверяет Origin, подпись свежего запуска, площадку, UID, существующего персонажа и сохранённое подписанное native-свидетельство. Затем владелец OAuth-сессии подтверждает продолжение на сайте с CSRF. Имя используется только как подсказка, не как доказательство личности.

Привязки хранятся приватно вне webroot в `private/social-links`, каталог 0700, файлы 0600. Одновременные записи защищены flock; записи атомарные. Нет автоматического объединения по email/имени/телефону. Запрещены другая площадка, истёкший/повторный код, другой OAuth-владелец, повторная привязка персонажа другому входу и замена существующей привязки. SocialSessions больше не вставляет users: персонаж должен существовать внутри соответствующей соцсети.

Публикация узкая: шесть PHP-файлов сайта, login.js, отдельный native-site-link.js и подключение в native HTML, маршруты Nginx. Игровой bundle native остался байтово прежним; SQL миграций, очистки данных, правок платежей и перезапусков FPM не было. Nginx прошёл проверку и reload.
