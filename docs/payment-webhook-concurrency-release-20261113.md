13 ноября 2026. Все операции публикации ограничены пакетом сайта. Native-клиенты, конфигурации миров и данные игроков не заменялись.

## Журнал webhook

Новый PaymentWebhook пишет received, verified и итог каждой попытки с отдельным attempt_id. Записываются только время, безопасный ID платежа, мир из ответа API, источник, результат и HTTP-статус приложения. Тело уведомления, API payload, секреты и сообщения исключений не пишутся. Неизвестные события отмечаются ignored, неверные запросы rejected_request, сбои — классом исключения и 503. Ошибки аудита закрывают обработку с 503 для последующего повтора провайдером. При повторе после уже выполненного начисления штатный settle возвращает already_credited.

Журнал /var/lib/pripyat-payment-webhooks/deliveries.jsonl доступен сервисному пользователю сайта; записи защищены flock и fflush, файл 0640, каталог 0750. Logrotate: ежедневно, 30 архивов, maxsize 10M, copytruncate. История покупки объединяет последние записи сверки и webhook, показывает источник, attempt_id и HTTP-результат. Чтение ограничено последними 2 MiB каждого активного журнала и 100 строками на платёж. Это ограниченная оперативная история, не бессрочный архив. HTTP-результат означает ответ приложения; получение ответа внешним провайдером сетью этим журналом не подтверждается.

Публикация: /var/backups/pripyat-webhook-audit-20261113T092704Z. Проверки PHP, php-fpm8.5 -t, nginx -t и logrotate --debug успешны. Реальные HTTPS-пробы без платежей: GET 400, неизвестное событие 200, некорректный JSON 503; все отражены в журнале. Они не обращаются к API провайдера и не начисляют ресурсы.

## Конкурентное начисление

tools/verify-payment-concurrency.py запускает отдельный mysqld --no-defaults --skip-networking --mysqlx=OFF с новым datadir в /var/tmp/pripyat-concurrency-*. Fixture отказывается от любого socket вне этого каталога. Две независимые PHP-команды доходят до mock provider одновременно; барьер отпускает обе после подтверждения их пересечения во времени. Используются общие InnoDB-таблицы только этого временного экземпляра. После проверки процесс завершается, каталог удаляется. Рабочий MySQL не подключается.

Прошли 14 сценариев: сайт, VK и OK в test/live, Telegram в live; для каждого одновременно один и тот же платёж и два разных платежа одному игроку. Один платёж: credited + already_credited, ровно одно начисление и одна квитанция. Разные платежи: два credited, ровно два начисления и две квитанции. Баланс и credited_at проверены отдельным соединением. Подменённых игроков в рабочих базах не создавали, миграций нет.

## TEST и PROD

Машиночитаемый отчёт: release-version-audit-20261113.json. Проверены серверные core/json и клиентские libs без приватных конфигураций, registry и журналов. Это аудит кода, не сравнение данных окружений.

Действующий основной бандл, подключённый обеими страницами: index.training-72a703779193.js. SHA256 одинаковый. Ранее выявленное различие index.js относится к запасному файлу, не к активному подключению: PROD добавляет только очистку вчерашнего остатка урона Седого при ошибке 69 и текст ошибки. После удаления двух этих вставок строки TEST/PROD полностью равны.

PROD дополнительно подключает native-avatar-sync.js и native-site-link.js. В общих PHP различаются четыре контроллера: bosses.php и habar.php — только комментарии; rewardlinks.php — аудит получения наград; users.php — cacheAvatar. Только на PROD присутствуют модели границы PROD, блокировки игровой сессии, платежей VK/OK, аудита и кеширования аватара. На TEST есть дополнительные старые training-бандлы, они не подключены исследованной страницей.

Следовательно, единой самой свежей копии всего проекта нет: PROD содержит более полный native runtime; локальная рабочая папка содержит отдельные незакоммиченные изменения Telegram/сайта/хабара; GitHub содержит воспроизводимый закоммиченный пакет. Нельзя автоматически заменять PROD локальной папкой или TEST. Для завершённого пакета webhook/оплат актуальные файлы опубликованы на сайте и сохранены в GitHub.
