Сервер создаёт персональный счёт XTR, сохраняя цену и награду. Pre-checkout сверяет владельца, валюту, сумму, срок и единственный checkout ID; ничего не начисляет. Начисление происходит только по successful_payment через защищённый webhook, в одной SQL-транзакции с журналом. Повторный charge/order не начисляется дважды. Для валют обе части SQL-сложения явно DECIMAL: сохраняется точность BIGINT при строковых PDO-параметрах. Энергия включает накопившуюся регенерацию; устаревшее клиентское сохранение не перезаписывает оплаченную энергию. Позднее подтверждение уже оплаченного счёта принимается после истечения срока создания заказа.

Клиент openInvoice не выдаёт награду: опрашивает сервер, обновляет users.get. Отмена ничего не начисляет. При задержке подтверждения предлагает повторный вход или /paysupport. Команда /paysupport сохраняет частное обращение, доступное разработчику через TG ЛОГИ. Событие возврата сохраняется в журнале; автоматического изъятия уже потраченных товаров и автоматической отправки возвратов нет — это отдельное решение поддержки.

Stars включены приватным флагом stars_enabled в /etc/pripyat/telegram-test.php. Секреты не находятся в Git/public. Webhook подписан на message, callback_query, pre_checkout_query.

Только проверенный Telegram ID 1355806786 (@ne_mafiya), внутренний player_id 18, имеет роль developer. Username сам по себе не является основанием доступа. Новый вход получает эту роль с сервера. Dev API повторно проверяет роль в БД; обычному игроку запрещены выдача ресурсов и чтение логов. Массовый сброс игроков запрещён. Eruda загружается отдельным чанком только разработчику: console/info, без сетевого инспектора. Кнопка TG ЛОГИ выводит очищенные серверные события и обращения поддержки.
