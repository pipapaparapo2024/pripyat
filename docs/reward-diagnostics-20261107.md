# Диагностика наградных ссылок

Опубликовано 07.11.2026 в native PROD и на сайте. Изменяется только диагностика; выдача ресурсов и её транзакция сохранены.

Журнал systemd: `journalctl -t pripyat-rewards --since today -o cat`. Доступ только администраторам сервера. Время даёт journal; записи JSON содержат stage, reason, world, player_id и SHA-256 кода (reward_hash). Полный код, URL, токены, cookie, почта и телефон не записываются. Для поиска конкретной ссылки вычислять SHA-256 локально/на сервере без передачи ссылки сторонним сервисам. Проверять одновременно мир и ID: ID разных миров не объединять.

Этапы: capture/received — сервер получил намерение; oauth_* — переход и этапы входа; bootstrap/delivered — код передан в подтверждённую игровую сессию; claim/requested — игрок запросил награду; claim_result/credited — транзакция выдачи подтверждена. Отказы: already, expired, notfound, target_mismatch, habar_date_missing, database_unavailable, transaction_failed. Bootstrap также отмечает intent_expired и ошибки входа/лимитов. Успех журнала выдачи не подменяет reward_link_claims — окончательное подтверждение находится в БД.

До подтверждения личности player_id=0; анонимный переход нельзя доказательно приписать человеку. Для ВК на этапах OAuth ID записывается только из подтверждённого native_vk_id; окончательный игровой ID и мир фиксируются при bootstrap и claim. Отсутствие callback после oauth_start означает отсутствие подтверждённого возврата; причину внутри страницы VK ID сервер не видит. Старые попытки задним числом не восстанавливаются.

Проверки: полный npm test — 799 файлов без падений, отдельные проверки audit, reward intent и сохранения кода при входе. Живой PHP-FPM smoke подтвердил capture и oauth_start без раскрытия кода и без выдачи награды; /auth/status HTTP 200. Сборка клиента не менялась.
