## Подтверждение

После публикации v778 владелец проверил игру и написал: «все успешно работает». Перед этим владелец отдельно подтвердил рабочую оплату ВК; после исправлений каталога подтверждена работа ОК. Это точка возврата для текущей закрытой native-версии ВК/ОК.

Статус относится к ВК54574178 и ОК512005669202 на новом VPS135.106.159.212, домен pripyat-game.ru. Доступ остаётся закрытым: разработчики входят, остальные получают технические работы. Telegram и самостоятельный сайт не считаются этим тегом подтверждёнными production-релизами. Их подготовленные исходники сохранены в общем снимке проекта, но при откате native ВК/ОК их развёртывания не менять.

## Точка возврата

На новом VPS создана закрытая архивная копия **уже работающего v778**:

/var/backups/pripyat-known-good-v778-20261104/native-runtime-v778.tar.gz

Архив проверен чтением списка файлов. Права каталога0700, архива0600. Он остаётся вне GitHub и может содержать приватные runtime-файлы. Это копия файлов приложения, **не резервная копия MySQL**. Текущие конфигурации /etc/pripyat и состояние оплат сохраняются отдельно; пароли из Git не восстанавливаются.

Для исходников создать отдельный checkout/worktree тега stable-v778; не делать git reset/clean поверх незавершённой работы. Полный commit SHA можно получить командой git rev-parse stable-v778^{commit}.

Перед серверным откатом:

1. Включить технические работы, остановить новые покупки и сделать закрытый backup текущих файлов и БД. Сверить ожидающие транзакции, не потерять платёжные подтверждения.
2. Развернуть тег или закрытый runtime-архив в отдельный каталог. Сверить manifest, секреты окружения, fixed app IDs, допуски, БД stalker/stalker_ok и обратные вызовы. Ничего не импортировать в MySQL автоматически.
3. Выполнить PHP lint, nginx -t, проверки подписи/доступа/цен/повторов. Архивные файлы не распаковывать без проверки прямо поверх работающего приложения.
4. Переключить только native PROD ВК/ОК. При изменении PHP перезапускать только pripyat-native-prod-fpm; Telegram, сайт и общий FPM не трогать. Проверить HTTPS, вход, сохранение и минимальную покупку владельцем.

**Откат кода не означает откат БД.** Не очищать/заменять игроков и платёжные журналы; изменения схемы и импорт дампов требуют отдельного согласования. Не запускать старые promote/sync скрипты, нацеленные на Beget155.212.211.202.
