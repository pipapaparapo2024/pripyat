# v786 — однократный зачёт урона друзей

07.11.2026. Серверное исправление bosses.php, клиентская сборка не изменяется.

При отсутствии подходящего boss_fight_session восстановление раньше вычитало полную сумму урона друзей, а затем повторно применяло те же строки через курсор. Теперь начальное HP учитывает собственный урон, а помощь друзей проходит ровно один раз через общий курсорный обработчик. Последующие запросы используют сохранённый курсор.

Контракт функций и все пять путей вызова проверены: friendsDamage, startFight, attack, useSedoy и claimKill. Блокировка строки и commit не менялись. Время старта боя и дружбы, помощь с другого босса/сложности, изоляция Седого и запрет получения помощи в соло сохранены.

Регрессионный тест исполняет настоящий PHP-контроллер. До исправления он воспроизводил ошибку: ожидалось 860 HP, получалось 760. После исправления проходят 320 проверок для восьми боссов и четырёх сложностей: восстановление, потеря кэша, загрузка сохранённого JSON, повторные запросы, поздняя загрузка друзей и следующий новый удар. Та же проверка выполняется на MySQL с TEMPORARY TABLE boss_damage_log, без изменения постоянных таблиц и игроков.

Публикация: native TEST и PROD, сайт, Telegram TEST. Telegram PROD не активируется. Замена производится точечно по двум исходным фрагментам, с проверкой исходной версии, PHP lint, резервной копией и повторным MySQL-тестом каждого опубликованного контроллера. Нет миграций, массовых сбросов и перезапусков служб.

Ранее завершённые бои и награды не пересчитываются. Уже сохранённое старым кодом ошибочное HP активного боя не исправляется принудительно: исправление действует при новом расчёте/восстановлении и для новых боёв.

Полный npm test: 97 базовых проверок и 800 тестовых файлов, 0 падений. После публикации каждый из четырёх контроллеров прошёл 320 проверок на MySQL с временной таблицей.
