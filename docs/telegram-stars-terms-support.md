# Telegram Stars: условия, поддержка и возвраты

Локально подготовлены условия цифровых покупок `/telegram-terms/`, явное подтверждение перед счётом, закрытая запись версии условий и времени принятия, обработка обращений через бота и ручной запрос возврата через Telegram Bot API.

## Покупка и согласие

- Клиент показывает наименование, количество ресурса, цену в Stars и кнопки «Условия», «Согласен», «Отмена».
- «Условия» открывает отдельную страницу сайта. После её просмотра игрок снова нажимает покупку и отдельно подтверждает согласие.
- Сервер сохраняет `Telegram ID`, `player_id`, версию условий и timestamp в приватном каталоге только выбранного окружения (`/var/lib/pripyat-tg-test/terms` или `...-prod`). На стороне API согласие не принимается из клиентского поля создания заказа: его проверяет серверная запись.
- После обновления текста меняется версия условий в `TelegramTermsConsent::VERSION`; новая версия требует повторного явного согласия.

## Поддержка

- В меню `/start` добавлена кнопка «Поддержка». Команды `/support` и `/paysupport` открывают то же меню.
- Сначала игрок выбирает «Платёж или Stars», «Покупка не появилась», «Вход или игра» либо «Другое», затем получает короткий запрос на одно сообщение. После ответа бот выдаёт номер обращения и подтверждает, что ответ придёт в этот же чат.
- `/paysupport текст` по-прежнему принимается для совместимости. После отправки обращения бот удаляет сообщение Force Reply; незавершённый ввод автоматически истекает через 30 минут.
- Владелец добавляет и отзывает сотрудников через `/supportplayers add <Telegram_ID>`, `/supportplayers remove <Telegram_ID>` и просматривает список через `/supportplayers list`. Только владелец может менять этот список.
- Владелец и назначенные сотрудники открывают закрытый inbox командой `/supportlist`. Страница содержит пять обращений; детали и ответ доступны через кнопки карточки, отдельные команды чтения/ответа не показываются. После ответа сообщение Force Reply удаляется. Возвраты Stars остаются серверной функцией, но команда `/refund` убрана из меню.
- Inbox показывает категорию, дату, игровой ID (если есть персонаж), Telegram ID и краткое описание. Идентификаторы помощников хранятся вне базы игры, отдельно для каждого окружения; список тестового доступа и роли разработчика не дают доступ к обращениям.
- Владелец видит список последних Stars-квитанций через `/paymentlist`. Возврат выполняется в два шага: `/refund` показывает подтверждение, затем `/refund CONFIRM <telegram_payment_charge_id>` вызывает `refundStarPayment`. API сверяет квитанцию с серверным журналом и запрещает неизвестные и уже возвращённые платежи.
- Возврат Stars не списывает игровые ресурсы автоматически. После денежного возврата владелец отдельно рассматривает игровую корректировку с учётом истории использования и применимых правил.

## Границы публикации

Это подготовка исходников. TEST/PROD runtime, команды BotFather, серверные файлы и базы данных не менялись. Перед доступностью игрокам нужны выбранное тестовое окружение, адресная публикация страницы и PHP/JS-обработчиков, затем установка команд BotFather и отдельная ручная проверка меню, покупки, согласия, обращения, ответа и возврата. На PROD не публиковать без отдельного поручения.

Тексты условий описывают игровой процесс и платежную поддержку; их соответствие конкретному статусу продавца, налоговому режиму и обязательным требованиям нужно подтвердить до широкого запуска.
