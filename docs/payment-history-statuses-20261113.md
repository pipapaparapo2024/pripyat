# Статусы истории платежей

Административная история считает покупкой только заказ с сохранённым `credited_at`: выдача ресурсов и внутренняя запись подтверждения выполняются в одной транзакции.

- `credited` — заказ зачислен и входит в число и сумму покупок.
- `expired` — API ЮKassa подтвердил отмену с причиной `expired_on_confirmation`; время на оплату истекло.
- `canceled` — API ЮKassa подтвердил отменённый платёж по другой причине.
- `pending` / `created` — оплата ожидается или платёжная попытка ещё не получила ID провайдера.
- `paid_uncredited` — API ЮKassa подтверждает `succeeded` и `paid=true`, но у заказа нет отметки зачисления. Такой заказ показывается отдельно для разбора.
- `unverified` — состояние нельзя надёжно классифицировать по текущему ответу API.

Неоплаченные и незавершённые попытки остаются видимыми для диагностики, но вынесены из истории покупок и её итоговой суммы. История чеков игрока уже выбирает только заказы со статусом `succeeded` и ненулевым `credited_at`. Существующие таблицы, платежи и данные игроков не изменяются; миграции не нужны.
