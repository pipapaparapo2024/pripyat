# Telegram TEST: друзья и команды бота

Опубликовано 02.11.2026 МСК, отдельный выпуск TG v1002. Только https://tg-test-pripyat-game.ru и @pripyat_game_test_bot. Структура 15 таблиц не менялась. VK/OK не публиковались.

## Пользовательские действия

- `/start`, `/play`: приветствие с предоставленным текстом и кнопкой входа; `/start f_<48 hex>` также обрабатывает персональное приглашение.
- `/friends`: текущие взаимные друзья, подтверждение удаления, переключение на «Не друзья», ссылка приглашения.
- `/others`: другие игровые аккаунты именно Telegram TEST, без себя и друзей. Это не контакты телефона и не список пользователей Telegram.
- `/invite`: постоянная активная ссылка владельца, без реферальной статистики/наград.
- В игровом окне друзей доступны «Друзья», «Не друзья», «Пригласить» и удаление.

Описание, аватар и изображения карточки бота пользователь решил оформить самостоятельно. Программно изменены только команды и webhook, не профиль. В приветствии /start и стартовом экране используются предоставленные текст и файл telegram-welcome.jpg; telegram-icon.jpg только сохранён в ресурсах, в профиль бота не устанавливался. Автоматических сообщений друзьям/уведомлений нет, requestWriteAccess не запрашивается.

Нажатие Telegram menu web_app «Играть» не отправляет боту отдельный update; приветствие в этом случае показывает сама Mini App с кнопкой «Войти в Зону». По /start приветствие приходит в чат. После пользовательского клика на ПК запрашивается requestFullscreen для tdesktop/macos/web-клиентов с SDK 8.0+. Неподдерживаемые клиенты продолжают обычный запуск; это запрос к Telegram, не гарантия полного экрана на каждой версии клиента. Мобильные клиенты этой веткой не меняются.

## Правила связи

Одна каноническая строка telegram_friendships с отсортированными внутренними ID. Проекции users.friends/friends_since обновляются у обоих участников под блокировками users в одном порядке, вместе с добавлением/удалением связи в одной транзакции. Повторное принятие существующей связи не обновляет friends_since_ms. Самодружба, несуществующая/отозванная ссылка не создают связь. При удалении не меняются валюты, награды, журнал урона и gym_pump_cooldowns. Повторное добавление даёт новую дату, старый урон боссам не переносится.

Для уже играющего получателя /start обрабатывается по аутентифицированному Telegram webhook. Для нового — открывает web_app URL с непрозрачным кодом; telegram-login сначала проверяет initData, создаёт/находит свой внутренний ID, только потом разрешает код. Подписанный start_param имеет приоритет над URL-параметром. Нельзя подменить получателя posted uid или выбрать произвольную пару аккаунтов.

Источником дружбы не являются users.setFriendsCache, friends scope или клиентский снимок. TelegramDatabase отбрасывает friendship-поля при любом legacy saveData(users, ...), поэтому запоздавшая запись игрового контроллера не восстанавливает удалённого друга. Перед игровыми действиями Telegram gateway синхронизирует каноническую проекцию; существующая логика взаимной помощи боссов получает актуальные связи и даты. Изменения не затрагивают legacy Database VK/OK.

Ссылки не автоматически отзываются после удаления конкретного друга: повторное явное открытие действующей ссылки снова добавляет пару (как согласованный переход без подтверждения). Функция блокировки конкретного игрока/ротации ссылки пользователем пока не вводилась; в БД есть revoked_at и сервер уже отвергает отозванные ссылки.

## Обработчик бота

`/server/telegram-bot.php` доступен только в TG nginx-vhost, отдельный FPM pool. Секрет webhook в `/etc/pripyat/telegram-test.php`, не в Git/клиенте. Проверяется X-Telegram-Bot-Api-Secret-Token; принимаются private chat и совпадающий from.id/chat.id. Никаких команд от имени другого игрока через callback. Телеграм-ID используется только для поиска внутреннего ID.

update_id обрабатывается под flock, завершённые обновления имеют отметку done в `/var/lib/pripyat-tg-test/bot-updates` (private directory). Дубли не создают повторных ответов после успешной обработки; операции дружбы идемпотентны сами по себе. При сетевой ошибке между отправкой ответа Telegram и записью отметки возможен повтор ответа при retry, но не повторное начисление/изменение даты дружбы. Оплату этот обработчик не обслуживает. Для длительной эксплуатации нужна ротация старых служебных отметок; сырые сообщения и токены туда не записываются.

Команды и webhook включены скриптом `tools/configure-telegram-friends-bot.py`. Копия настроек до изменения `/var/backups/telegram-friends-bot-20261101212335`; секреты не выводились. Последний TG выпуск: `/var/backups/telegram-test-release-20261101212139` (91 файл и 2926 ресурсов).

Живая проверка пользователем: /start у тестового бота; /invite от аккаунта A → ссылка аккаунту B → /friends у обоих; повтор ссылки не дублирует друга; удалить через /friends → связь пропадает у обоих; снова открыть ссылку → новая дружба.
