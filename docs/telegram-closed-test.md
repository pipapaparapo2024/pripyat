## Доступ

Постоянный владелец — Telegram ID 1355806786 (@ne_mafiya). Основание прав — числовой ID проверенного отправителя личного сообщения, не username и не роль developer.

- `/allow 123456789` — разрешить вход указанному Telegram ID.
- `/deny 123456789` — отозвать доступ, включая последующие запросы существующей сессии.
- `/access_list` — список допущенных ID, включая владельца.

Команды доступны только владельцу в личном чате с ботом; в группах не исполняются. Меню владельца настроено отдельной областью Bot API. Другим пользователям команды ничего не меняют. Разрешение играть не выдаёт DEV/Eruda. Доступ владельца нельзя отозвать. Допуск по username не поддерживается.

Человек открывает бота и отправляет `/start`. Бот сообщает о закрытом тесте и показывает Telegram ID. Человек пересылает ID владельцу; после `/allow ID` заново открывает игру. Самого бота и публичную страницу могут найти другие люди, но игровые данные и действия закрыты.

Список: `/var/lib/pripyat-tg-test/access.json`, вне public/Git; права 0600, Unix-владелец pripyat-tg-test. Отдельный flock и атомарный rename защищают параллельные изменения. Отсутствующий файл означает доступ только владельцу; повреждённый не открывает доступ посторонним. Деплой список не сбрасывает.

Подписанный вход проверяется до создания игрока/сессии; каждый API-запрос проверяет доступ по Telegram ID из серверной связи; бот проверяет команды/кнопки и pre_checkout_query. Ссылки друзей доступ не дают. После отказа API клиент показывает блокирующий экран; после восстановления допуска нужно перезапустить Mini App. Уже оплаченные successful_payment/refunded_payment обрабатываются и после отзыва; /paysupport остаётся доступен прежним покупателям. Принятое до отзыва действие не отменяется задним числом.

## Аватары

`telegramavatars.get` принимает внутренний player_id, требует допущенную сессию и разрешает фото допущенного зарегистрированного игрока. Сервер вызывает getUserProfilePhotos/getFile и скачивает JPEG с api.telegram.org. Клиент не задаёт произвольный URL/путь. Проверяются размер (до 2 МБ), формат и размеры изображения. Ссылка с токеном бота клиенту не возвращается.

Кеш `/images/telegram-avatars/<HMAC>.jpg` не содержит ID в имени. Положительный/пустой результат кешируется на час, временная ошибка — на минуту. Отсутствующее при следующем обновлении фото удаляется. Если Telegram не отдаёт фото, показывается нейтральная заглушка. После смены фотографии может потребоваться обновление кеша и повторный вход.

Telegram runtime кеширует запросы по внутреннему ID; общий helper и resolver профилей/рейтингов используют его. Старый вызов HUD без VK ID преобразуется в собственный внутренний ID. VK/OK ветки сохранены. Telegram JS-чанки имеют contenthash в имени для обновления клиентского кеша.
