## Финальное окно обучения

Внутри VK/OK оно уже отправляет припятское friends-permission-request, обработчик вызывает runtime.requestFriendsToken, затем получает друзей. В Telegram friendsPermission=false: контакты/социальные друзья не запрашиваются, игровая дружба по ссылкам. Имя и доступное фото относятся к профилю входа, не к универсальному согласию на сбор данных. Телефон/email для игровых функций не запрашивать без отдельной необходимости.

Локально усилен _requestFriendsScope: пустой/нестроковый токен или явно возвращённые права без friends не записывают успешное согласие, не меняют рабочий токен и не запускают загрузку друзей. Отсутствие scope у старого SDK допускается ради совместимости; реальную доступность списка подтверждает вызов API. Отдельно объясняются отказ в правах и ошибка получения списка после выдачи разрешения. Окончание обучения не блокирует игру при отказе; повтор доступен через существующую кнопку друзей.

Веб-вход и его permission-adapter ещё не реализованы. VK ID SDK поддерживает OAuth 2.1, но документации SDK недостаточно, чтобы обещать friends.get для конкретного веб-приложения. Нужны настройки/доступные scope в кабинете приложения и живой тест его токена. Для ОК friends.get требует VALUABLE_ACCESS и сессию внешнего приложения. Нельзя выдавать синтетическое разрешение или копировать токен из другой вкладки ради обхода ограничений. Если API не разрешает друзьям работать на сайте, обсудить с пользователем ограничение/альтернативу до обещания паритета.

## Telegram: отличать игровой TEST от тестовой сети

Stars уже реализованы в прежнем TG TEST, но тот бот был в обычной сети: название TEST не делало звёзды бесплатными. Сейчас в новом VPS Stars не включались.

Добавлена локальная поддержка bot_api_environment='test' в TelegramBotClient и точках его создания: запросы идут на https://api.telegram.org/bot<TOKEN>/test/METHOD. Обычный режим сохраняет прежние URL. Скачивание файлов использует соответствующий test base_file_url. Ошибка/неизвестный режим не переключает клиент автоматически на production.

Инструкция для Telegram Desktop: Настройки → Shift+Alt+правый клик по Add Account/«Добавить аккаунт» → Test Server; войти в отдельную тестовую сеть, создать там аккаунт и бота через тестовый @BotFather. Если пункт отсутствует, сверить версию клиента с актуальной документацией. Это инструкция по официальной документации, не действие, выполненное агентом на аккаунте пользователя.

Приватный шаблон нового VPS: /etc/pripyat/telegram-test-network.json, 0600. enabled=false, bot_api_environment=test, bot_token пустой, отдельный webhook_secret. database=stalker_telegram_sandbox — пока только предложенное имя, такая БД этим этапом НЕ создавалась. owner_test_telegram_id и allowed_test_telegram_ids должны относиться к тестовой сети. Токен не отправлять в чат/Git; записать в приватный файл через SSH/SFTP. Полный запуск потребует отдельного vhost/config/хранилища и адаптации нынешнего TEST-only gateway к нему. Не менять bot_api_environment на существующем общем TG-контуре с обычными аккаунтами.

Создание песочницы и изменения существующих схем предварительно согласовать. Бесплатные тестовые покупки не должны выдавать товары в обычную БД персонажей. До подключения тестового бота интеграционный тест Telegram не проводился, реальные Stars не списывались.

## ЮKassa

Тестовый магазин поддерживается до заключения договора, используются его shopId и секретный ключ. API общий, тест определяется магазином/реквизитами; backend должен проверять payment.test === true, статус, сумму, валюту и собственную запись заказа перед начислением. Тестировать повторы webhook, отмену, задержку подтверждения, подмену суммы/получателя, возврат и сбой транзакции. Возврат пользователя со страницы оплаты не является подтверждением покупки.

Приватный шаблон: /etc/pripyat/yookassa-test.json, 0600, enabled=false, shop_id/secret_key пустые, require_test_payment=true. Не использовать боевые ключи. В текущем коде ещё нет интеграции/таблиц журнала ЮKassa; SQL не применялся. Сначала подготовить состав заказов/транзакций и получить согласие на необходимые новые таблицы. Заказ связывать с подтверждёнными platform + player_id сервером, а не с posted параметрами. Для обычного сайта покупка должна менять соответствующую БД ВК/ОК/ТГ; отдельной БД «сайта» нет. Для тестового магазина не смешивать бесплатные награды с будущим боевым прогрессом.

Нативные покупки VK/OK сохраняются; Stars остаются для Telegram Mini App; ЮKassa — только для самостоятельного сайта. Конфигурацию тестовой оплаты определяет сервер, не URL/клиентский флажок. Реальные покупки не выполнялись. Перед публичным включением отдельно сверить правила платформ и платёжные условия.
