## 4. Обучение: согласованный сценарий

Основное окно Седого: пользовательский файл `C:/Users/HONOR/Desktop/vk_game/обучение/попап обучение .png`. Канонический игровой файл: `assets/images/попап обучение.png`. Их SHA-256 сравнивался, совпадает.

Порядок существующего тура: Двор → Зона → База → Хабар → Боссы → Сводка → Шмотки → Сидорович; затем валюта, финал, разрешение. Начальный интро-попап и ввод позывного сохранены.

После открытия каждой вкладки:
1. По центру появляется тот же попап с текстом соответствующей реплики.
2. Игра за окном заблокирована, играет озвучка.
3. Во всех окнах доступна **«Продолжить»**: закрывает объяснение и останавливает текущую речь. Поздний callback не должен продвигать шаг повторно.
4. При окончании речи окно описания вкладки закрывается автоматически, запускается практическая подсказка. При отключённом/неисправном звуке игрок читает и нажимает «Продолжить».

Практические действия:
- Зона: открыть Кордон → один раз выполнить действие с однократной тратой энергии → выйти из локации → выйти из списка локаций.
- Если Кордон уже завершён или энергии недостаточно, показать объяснение и дать выход; не списывать энергию искусственно и не зависать.
- База: открыть первую страницу → один раз перелистнуть вправо → выйти.
- Остальные вкладки: текст/озвучка → указатель на выход, без обязательной покупки, игры, боя или расходов.
- Во Дворе во время урока мигают все 4 игровых облака, 3 облака сухарей и облако 2048. Не мигать только четырьмя играми.
- Вместо кружка теперь **мигает сам целевой спрайт кнопки/файла**. Его исходная alpha восстанавливается при уходе со шага. Рука остаётся.

## 7. v732: зум, кеширование, 2048

### Зум и шрифты

Пользователь увеличивает игру **жестом**, а не увеличивает готовый скриншот. Реальный рендерер в его диагностике: WebGL 2.0, PixiJS 6.5.10 (Tolmasoft/PIXI.animate).
Раньше resize на каждом движении жеста менял буфер canvas, что давало чёрный кадр.
Теперь в `_client/src/index.js`:
- `_stableBufferInitialized` допускает выделение/resize буфера только при первой настройке; разрешение при старте ограничено 2–3.
- CSS вписывает игру в окно, логическая сетка 1280×720.
- `_textPixelDensity = targetRes * pinchDensity()` обновляет требуемую плотность **текстур текста** отдельно.
- `modules/text-quality.js` пересчитывает Text.resolution с учётом масштаба, поддерживает загрузку шрифтов и лимит 4.
- interaction.resolution равен фактическому renderer.resolution, а не меняющейся желаемой плотности текста.
- `modules/pinch-density.js` учитывает жест внутри iframe, где visualViewport.scale может оставаться 1; избегает двойного умножения native zoom/DPR.

Тест выполняет реальное тело resize guard и доказывает отсутствие повторного выделения framebuffer; реальные Pixi CanvasRenderer и карта нажатий также проверены. **Это не заменяет визуальную проверку чёрного кадра в WebGL-фрейме ВК/ОК.** Она ещё ожидается от пользователя. При очень большом увеличении исходные растровые картинки всё равно имеют конечное разрешение; не обещать векторное качество всех ассетов.

### Кеширование

Пользователь выбрал «загружать заново при каждом входе, повторно использовать внутри сессии».
`modules/asset-version.js` добавляет локальным images ключ `asset_v` с версией + идентификатором входа. Это не полное отключение HTTP-кеша всех MP3/шрифтов/JS и не изменение глобальных nginx-заголовков. Формулировать точно. Ресурсы внутри текущей сессии остаются в кеше Pixi/браузера.

### 2048

Отменённые касания и два пальца не должны отправлять ход; обработчики снимаются при закрытии/переподключении. Начало жеста проверяется по плиткам поля при наличии global point.
